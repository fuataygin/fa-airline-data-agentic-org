# FA Airline Data — Agentic Organisation

A fully agentic five-agent organisation, built on Google's **Gemini API
(Interactions API)**, that researches, designs, builds, markets, and manages
a real aviation-analytics product — end to end, with an unbroken hand-off
chain and a genuine live data connection.

```
ARIA (Researcher)  →  NOVA (Designer)  →  FORGE (Maker)  →  ECHO (Communicator)  →  ATLAS (Manager)
 queries the live       designs the         writes &            writes the             reviews the
 Google Sheet           methodology &       RUNS working         GTM package             whole chain,
 live, finds the        output spec         Python code          using FORGE's           writes exec
 opportunity                                 against the          real live               summary +
                                             live sheet           output                  90-day plan
```

Each stage's **full text output is the next stage's input** — see
`pipeline.py`. Nothing is faked or pre-scripted: every agent call goes to
the real Gemini API, and the Maker's product is generated code that is
then actually executed against the live dataset before the Communicator
and Manager ever see it.

## What this is built around

**FA Airline Data** is a company that turns a live Google Sheet — 30
airlines' financials, Boeing/Airbus/COMAC fleet orders, regional passenger
traffic, top global routes, and major aviation incidents, 2010–2026 — into
a real analytics product. The agents decide *which* product; nothing about
the product is hardcoded in advance (see "How the opportunity is chosen"
below).

## The live data connection

`tools/sheets_tool.py` queries Google Sheets' public CSV export endpoint
**at the moment of use** — a fresh `requests.get()` on every call. Nothing
about the dataset is cached, hardcoded, or copy-pasted into any prompt or
any file in this repo.

It's wired in two ways:

1. **As a real Gemini function call.** ARIA (the Researcher) is given the
   `fetch_faairlinedata_tab` function tool. The model itself decides which
   tabs to query and how many times, via the Interactions API's
   function-calling loop implemented in `agents/base_agent.py`.
2. **Inside the generated product itself.** FORGE (the Maker) is required
   to `from tools.sheets_tool import fetch_tab` in the code it writes, so
   the tangible artefact this org ships also queries the sheet live, every
   time it's run — not just once during the pipeline.

> The sheet must stay shared as **"Anyone with the link can view."** If you
> swap in your own private sheet, either keep it link-shared or replace the
> internals of `fetch_tab()` in `tools/sheets_tool.py` with an
> authenticated `gspread`/Google Sheets API call — every caller in this
> repo goes through that one function.

## How the opportunity is chosen (nothing is pre-baked)

This repo does not hardcode "the product FA Airline Data builds." ARIA is
instructed to query the live sheet, cross-reference at least two tabs, and
find one sharp opportunity herself — in practice (given the dataset's
2024–2025 content) she typically converges on something like a **Boeing
exposure / recovery index across the 30 airlines**, cross-referencing the
`fleet_orders`, `aviation_incidents`, and `airline_financials` tabs. NOVA
then names and specs it, FORGE builds and runs it live, and the rest of
the org reacts to whatever real numbers come out. Because ARIA's tool
calls are live, re-running the pipeline against an updated sheet can
legitimately surface a different opportunity.

## Repository layout

```
config.py                    # shared constants (sheet ID, model, output dir)
main.py                      # CLI entry point — loads .env, runs the pipeline
pipeline.py                  # orchestrator: the unbroken 5-stage hand-off chain

agents/
  base_agent.py               # shared Agent class + Gemini Interactions API function-calling loop
  researcher.py                # ARIA — has live sheet tool access
  designer.py                  # NOVA — turns the brief into a spec
  maker.py                     # FORGE — writes real, runnable Python
  communicator.py              # ECHO — GTM package, grounded in real output
  manager.py                   # ATLAS — chain review + executive summary

tools/
  sheets_tool.py               # the ONE live external data connection

products/
  bers_engine.py                # generated by FORGE at run time (not hand-written)

outputs/                       # every agent's artefact, written per pipeline run
tests/
  test_sheets_tool.py          # live smoke test of the data connection
.github/workflows/ci.yml       # GitHub Actions: runs the live smoke test
```

## Setup

```bash
git clone <this-repo>
cd FA-Airline-Data-AgenticOrg
python -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt
cp .env.example .env
# edit .env and paste in your GEMINI_API_KEY
```

Get a Gemini API key at **[aistudio.google.com/apikey](https://aistudio.google.com/apikey)**
— sign in with a Google account, create a key, and (for anything beyond
light free-tier testing) enable billing on the associated Google Cloud
project. No separate Google Cloud Console setup, App Script, or GCP project
configuration is required beyond that — the key alone is enough to call
the Gemini API.

## Run it

```bash
python main.py
```

This runs the full five-agent chain and:

- prints a live console log of each stage, including ARIA's actual function calls
- writes every agent's output to `outputs/01_...` through `outputs/05_...`
- writes FORGE's generated product to `products/bers_engine.py`
- **actually executes** that product against the live sheet and saves the
  real console output to `outputs/03b_maker_real_execution_output.txt`

Re-run the built product on its own any time, independent of the pipeline:

```bash
python -m products.bers_engine
```

Run the live data-connection smoke test:

```bash
pytest tests/test_sheets_tool.py -v
```

Quick manual check of the tool in isolation:

```bash
python -m tools.sheets_tool
```

## Publishing a public, no-login showcase (GitHub Pages)

**Why this exists:** GitHub Pages only serves static files — it can't run
`pipeline.py`. And the Gemini API key is a secret: putting it in
client-side JavaScript on a public, unauthenticated page would let anyone
who opens their browser's dev tools copy it and spend your API credits.
There's also no safe way around this by having the browser call Google
Sheets directly either — Google's CSV export endpoint doesn't send CORS
headers, so a public page's own JavaScript can't fetch it live.

So instead: `build_site.py` runs **locally**, where your real `.env` key
already lives, reads the **real** files your last `python main.py` run
produced in `outputs/`, and bakes them into a plain static HTML page with
no key, no backend, and nothing secret in it — safe to publish anywhere,
fully public, no login required.

```bash
python main.py          # produces real outputs/ + products/bers_engine.py
python build_site.py    # turns those real outputs into docs/index.html
```

Open `docs/index.html` locally first to check it looks right, then commit
and push:

```bash
git add docs/
git commit -m "Publish showcase site"
git push
```

**Enable GitHub Pages (one-time setup):**
1. On GitHub, go to your repo → **Settings → Pages**
2. Under **Build and deployment → Source**, choose **Deploy from a branch**
3. Branch: **main**, Folder: **/docs** → **Save**
4. GitHub gives you a URL like `https://YOUR-USERNAME.github.io/YOUR-REPO/`
   — live in a minute or two, no login required to view it

To update the published page later, just re-run `python main.py` (for a
fresh live pipeline run) or `python build_site.py` (to re-bake the current
`outputs/` into the page), then commit and push `docs/` again.

**What this page is, honestly:** a real, unedited snapshot of one pipeline
run — not a live-refreshing dashboard. If you specifically want a *fully
live*, publicly-triggerable version (visitors cause a real Gemini call on
each page load), that needs a small server-side component to hold the API
key safely — e.g. a Cloudflare Worker or Vercel serverless function that
the static page calls, rather than the key ever reaching the browser. That's
a genuinely different, larger build than "just enable Pages" — happy to
scope it out if you want to go that route.

## Design notes / honesty about limitations

- **FORGE's code is LLM-generated at run time.** `pipeline.py` executes it
  and, if it fails, still lets the chain continue with the real error
  output rather than silently patching or hiding the failure — ECHO and
  ATLAS see (and react to) genuine failures, not sanitised ones. If you
  want a guaranteed-clean demo for a presentation, run `python main.py`
  once beforehand, check `outputs/03b_maker_real_execution_output.txt`
  says `SUCCESS`, and keep that run's `products/bers_engine.py` committed.
- **Model choice.** All agents default to `gemini-3.6-flash` (GA, stable).
  Override per run with the `GEMINI_MODEL` environment variable if you
  want to try `gemini-3.1-pro-preview` for higher-quality Designer/Manager
  output (preview status, no free tier), or `gemini-2.5-flash` for a
  well-established fallback.
- **API surface.** This repo uses Google's **Interactions API**
  (`client.interactions.create`), the API Google recommends for all new
  projects as of June 2026, rather than the older `generateContent` loop.
  It requires `google-genai >= 2.3.0`. If you'd rather build against the
  older, more widely-documented `generateContent` + manual chat-history
  approach, the change is isolated to `agents/base_agent.py`.
- **Cost/quota.** One full pipeline run makes 5+ Gemini API calls (more if
  ARIA calls the sheet tool several times). Nothing runs in a loop or
  retries indefinitely. `gemini-3.6-flash` has a modest free tier; heavy
  team testing will eventually need billing enabled on the Gemini API key.
